contracts/policy

Policy contract

Rust, near-sdk 5, 67 unit tests. Holds the USDC, the vendors, the limits and the orders, decides every claim, and verifies 1Click's quote signature with env::ed25519_verify before a cross-chain payment.

app/src/agent.ts, ai.ts

Agent

Watches an inbox folder and the Telegram inbox, has each PDF read in NEAR AI Cloud's TEE, builds the claim and calls request_payment with its one function-call key.

app/src/relayer.ts

Relayer

Takes the agent's NEP-366 meta transactions and pays their gas. It forwards request_payment from the agent and nothing else.

app/src/executor.ts, quote.ts

Executor

A plain process with no AI and four methods: settle, mark_settled, mark_settlement_failed, sync_dao_proposal. It brings a 1Click quote for each queued payment; the contract checks it. Mainnet only.

web/console.html

Console

The back office in one static page: Overview, Invoices, Attention, Vendors, Orders, Analytics, Settings and Inbox. Renders the PDF, calls the enclave, checks the receipt and signs request_payment in the browser.

app/src/mcp.ts

MCP server

Ten tools, so any assistant can drive a treasury with the agent's powers, plus two housekeeping tools that use the executor's and the owner's keys when the environment has them.

Run it yourself

Testnet in five steps.

Prerequisites: Rust stable with the wasm32-unknown-unknown target, Node 22+, poppler (pdftoppm, pdftotext), Python 3 with reportlab, and near-cli-rs for the accounts.

  1. 1
    Contracts

    Build and test the contracts.

    (cd contracts/policy && cargo test && ./build.sh) (cd contracts/test-usdc && cargo build --release --target wasm32-unknown-unknown) (cd contracts/registry && cargo test && ./build.sh)

    See 67 passed for the policy contract and bursar_policy.wasm: 462773 bytes.

  2. 2
    App

    Install and test the app.

    cd app && npm install && npm test

    See 14 passing tests: signature recovery, receipt tampering, a real NEAR AI Cloud receipt, the offline parser, money parsing, and a real 1Click quote rebuilt byte for byte.

  3. 3
    Accounts and deploy

    Create three faucet accounts and run setup.

    near account create-account sponsor-by-faucet-service you.testnet autogenerate-new-keypair save-to-keychain network-config testnet create near account create-account sponsor-by-faucet-service you-b.testnet autogenerate-new-keypair save-to-keychain network-config testnet create near account create-account sponsor-by-faucet-service you-c.testnet autogenerate-new-keypair save-to-keychain network-config testnet create near tokens you-b.testnet send-near you.testnet '9.5 NEAR' network-config testnet sign-with-keychain send near tokens you-c.testnet send-near you.testnet '9.5 NEAR' network-config testnet sign-with-keychain send npx tsx src/cli.ts setup --root you.testnet

    About 25 NEAR in one account; the faucet gives 10 per account. setup creates the treasury, agent, executor and vendor accounts, a test USDC token and a Sputnik DAO, deploys and funds the contract, and leaves the agent a single function-call key. If it stops on a network error, run it again: it resumes.

  4. 4
    Read the invoices

    Start the relayer and read the invoices.

    set -a; source .env.testnet; set +a npm run relayer & mkdir -p ../invoices/inbox && cp ../invoices/samples/0[1-4]-*.pdf ../invoices/inbox/ npm run agent -- --once --offline

    The offline parser only understands the sample invoices. Drop --offline to read them with NEAR AI Cloud inside the TEE (needs NEAR_AI_API_KEY).

  5. 5
    Check

    Check and verify.

    npm run dev status npm run dev verify 1

    See four decisions: paid, queued, held for the DAO, refused for a changed payout. verify checks the TEE receipt of payment 1, written when the invoices were read with a NEAR AI key.
